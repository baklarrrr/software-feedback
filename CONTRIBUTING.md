# Giving useful feedback

1. Search [existing issues](https://github.com/baklarrrr/software-feedback/issues). If the same problem is already there, add a short, relevant detail rather than opening another report.
2. Choose the software and report type. Give the version shown in the application or on its website; write `Not sure` if you cannot find it.
3. For a bug, describe what you expected, what happened, and the smallest steps that reproduce it. Include your operating system and browser when relevant. Do not include a machine name, serial number, account name, or full file path.
4. For a request, explain the task you are trying to accomplish, the difficulty, and a possible improvement. Suggestions can be discussed without promising implementation.

## Public and private information

GitHub issues and comments are public. Your GitHub username is visible. These forms do not ask for your name, email, phone number, location, project files, or diagnostic uploads. GitHub still lets contributors edit reports and add attachments; the forms cannot prevent every disclosure.

Check your text before posting. Replace private filenames and paths with neutral examples. Remove credentials, tokens, personal information, client material, and anything you do not have permission to share. Do not paste raw logs or attach screenshots or files containing that information.

Suspected vulnerabilities belong in [GitHub's private reporting route](https://github.com/baklarrrr/software-feedback/security/advisories/new). That route is for security concerns, not ordinary feature requests.

## If something private was posted

Edit it out promptly. Editing or deleting a public post cannot recall copies, notifications, or cached versions. If credentials were exposed, revoke or rotate them through the service that issued them. Do not repost the sensitive material to explain the problem.

## Discussion and review

Keep discussion constructive, relevant, and free of personal information, harassment, spam, and unsolicited advertising. Maintainers may redact inappropriate information and close or lock abusive or unrelated threads using GitHub's moderation tools.

Product labels identify the software; `bug` and `enhancement` identify the report type. A label records triage, not proof that a defect has been confirmed. Follow the issue for questions and updates. No response or resolution deadline is promised.

Application source is not available for code pull requests through this hub. Feedback is welcome through the issue forms. Downloads, application terms, and release information remain on [bakar.ca/software](https://bakar.ca/software/).
