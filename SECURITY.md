# Reporting a security concern

For a suspected vulnerability in Earthlight, Histogrammer, or Timelapser as published on Bakar.ca, use [Report a vulnerability](https://github.com/baklarrrr/software-feedback/security/advisories/new). A GitHub account is required. GitHub's private reporting workflow shares the report with the repository maintainers rather than publishing a public issue.

Include the software, affected version, impact, and minimal reproduction steps. Use synthetic examples. Never send passwords, API tokens, personal data, private client projects, or unnecessary files, even in a private report.

Do not publish exploit details in a public issue. Keep any investigation within systems and data you own or are authorized to test. For a vulnerability in a third-party service or dependency, use that project's own reporting policy.

Current release links are on [bakar.ca/software](https://bakar.ca/software/). No security audit, bounty, support period, response time, or fix date is promised by this policy. A report can be assessed without guaranteeing a particular outcome. Any later public advisory should omit personal and confidential information.
